## 重点问题

### #6：整份插件文件语法错误（阻断）

`plugins/shared/exam-ui.mjs` 尾部把最后 6 行重复粘贴了一次：

```js
  return () => {
    for (const dispose of cleanups.splice(0)) dispose();
  };
}
}

  return () => {                                  // ← 顶层 return
    for (const dispose of cleanups.splice(0)) dispose();
  };
}
```

顶层出现 `return` → `SyntaxError: Illegal return statement`。这个文件是阅读/听力练习页的渲染与行为核心，一旦合并进来，`/plugin-assets/shared/exam-ui.mjs` 加载即失败，练习页整体不可用。

`tsc --noEmit` 不会检查 `.mjs`，所以类型检查是绿的、看起来没问题；只有真正 import 时才会炸。`npm run build` 也拦不住——`plugins/` 不在 tsconfig 的 `include` 里，也不经过 vite 打包。裁掉重复的 6 行后，#6 + #8 的 51 个测试全过。

修完语法后的 #6 还有三个低优先级问题：`locateAnswer` 在原文加载失败时直接 `return`，用户点了没有任何提示（`:1187`）；同一条证据在原文出现多次时永远取第一次（`findEvidenceMatch` 取 `exact[0]`，`:157`），忽略 `preferredSection`；`data-answer-question` 用空格拼接多个题号、却用 `~=` 精确匹配，题号里一旦含空格就永远匹配不上（`:270`/`:1156`）。XSS 方面是干净的：所有插值都过了 `text()`，用 `<img onerror>` 探过原文、题号和题号标签，均被转义。

### #7：CSS 括号不平衡 + 媒体查询规则漏到顶层

`src/styles.css` 末尾（1399–1403 行）在 `@media (max-width: 520px)` 块之后又平铺了一遍同样四条规则，并多一个 `}`：

```css
@media (max-width: 520px) { … }        /* 1394-1398 正常 */

  …exam-audio-bar { display: flex; flex-wrap: wrap; }   /* 顶层，所有宽度生效 */
  …exam-audio-tabs { flex-basis: 100%; }
  …exam-audio-track { min-width: 60px; }
  …exam-audio-vol { margin-left: auto; }
}                                                       /* 多余 */
```

后果：桌面端（1440×900）听力练习只要音频分多段，波形条就被强行换成两行——本该只在手机上生效的排版。浏览器会静默丢弃多余括号，不会报错，所以很难发现。

### #4 / #5 / #7：都是为了 #6 才存在的碎片

elaoshi666 这 7 个 PR（#3–#9）其实是一个功能被拆成了 7 个只有一两个文件的碎片，单看每个都很小，但缺一个就整条链路不通：

- **#6** 在 `exam-ui.mjs:1109` 调 `buildAnswerTargets(activity, result)`，但两个插件调用方都不传 `result`（只有 `plugins/{reading,listening}/browser.mjs:13-25` 的 ctx）→ `result` 恒为 `null` → 定位功能静默失效：按钮渲染出来了，点了没反应，原文里也永远不会出现高亮。**#4 和 #5 补的正是这个参数**，单独合入是空操作，跟 #6 一起才生效。
- **#6** 渲染的新类名（`is-answers-off`、`mark.exam-transcript-answer`、`exam-transcript-answer-nav`、`exam-answer-locate` 等）在 main 的 `styles.css` 里一条规则都没有，**#7 补的就是这些样式**。没有 #7，"显示/隐藏答案句"只会翻转 `aria-pressed`，实际什么都藏不住；高亮退回浏览器默认的黄色 `<mark>`。
- **#8** 的测试只断言 HTML 字符串里出现 `data-locate-answer="q1"` 之类的标记，没有任何一个测试真正调用 `mountExamBehavior`。所以它在"修好语法错误的 #6"上 8/8 全绿，却完全测不出上面两个失效点——绿灯是假象。

也就是说：#6 给出实现、#4/#5 把它接上线、#7 给它样式、#8 给它（很浅的）测试、#3/#9 给它文档。**合就必须整组合，并先修掉 #6、#7 两个阻断项。**

### #1：服务端逻辑扎实，两处客户端问题要修

69 个测试全过、typecheck 通过、`vite build` 通过；SQLite 与 Neon 两条 apply 路径都改成事务内并行校验，并发 bootstrap/确认由原子闸门去重，没发现数据损坏或安全回归。需要修的是两个客户端问题：

1. **`src/services/api.ts:17` 无条件用 `AbortSignal.any`**。这个 API 要 Chrome 116+ / Firefox 124+ / Safari 17.4+。老 iPad（iPadOS 16.x）打开应用会直接卡在骨架屏，`bootstrap()` 抛 `AbortSignal.any is not a function`，点"重新加载"对每个请求重复同一错误。项目其他部分瞄准 es2022，这个 API 是唯一的硬门槛。改成特性检测 + 回退即可。
2. **30 秒客户端超时没有长于导师接口的服务端预算**。`ai-client.ts:40` 的 AI 调用默认就是 30 秒，教练接口在 AI 之前还要做快照和历史查询；模型耗时约 29 秒时，客户端 30 秒先断，服务端随后照常写入。用户看到"操作结果尚未确认"，点重试 → 又一条用户消息、又一次 AI 调用，对话历史和 token 都翻倍。把客户端超时提到 60 秒、或给 `/api/coach` 单独放宽即可。

其余是边角 UX 和测试覆盖：方案里某道题与已完成任务重叠时会把整份有效方案判失败（`plan-rules.ts:9`）；轮询进入 `recoverable` 后永不恢复（`plan-polling.ts:20`）；一次失败轮询设下的错误横幅不会被后续成功清除；`ApiError.applied` 设了但没人读，503 已提交的变更客户端仍当失败；`plan_date` 为 NULL 的历史方案服务端 409、仓储层却当成"今天"。

另外：`.github/workflows/api-01-checks.yml` 本身有效，四步（`npm ci` / typecheck / test / build）都实测能跑；但 `main` 上原本没有 `.github/`，且 PR #1 来自 YMYWX 的 fork，合并前这个检查不会自动卡住本仓库的 PR。
